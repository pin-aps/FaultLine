# FaultLine

FaultLine forecasts the probability of an **M3.5 or larger earthquake within the next 30 days** on each of the 10 named sections of the San Andreas fault system (Parkfield, Creeping, Mojave, Coachella, and others). It combines the USGS earthquake catalog, GPS strain rates from 8 UNR GPS stations, and USGS fault geometry, and compares four forecasting approaches:

- **ETAS**: the standard statistical aftershock model, used as the seismology baseline
- **Historical base rate**: each section's past event frequency, with no features
- **XGBoost**: gradient-boosted trees on daily features
- **LSTM**: a neural network on 60-day feature sequences

The central question is whether GPS strain rate, which ETAS does not use, improves forecasts.

Use `python -m pip` rather than `pip`, since `pip` alone is not always on the PATH on Windows.

## How to run

The raw data is already included, so no downloading is needed. Open the notebooks in VS Code or Jupyter and **Restart and Run All** in this order, since each one uses files produced by the one before it:

| Order | Notebook | What it does |
|---|---|---|
| 1 | `data_exploration.ipynb` | Loads and checks the raw earthquake, GPS and fault data |
| 2 | `feature_engineering.ipynb` | Assigns earthquakes to fault sections and builds daily features: seismicity rates, b-value, GPS strain rate, recent-large-event features, reliability flags. Writes `data/processed/features.parquet` |
| 3 | `etas_baseline.ipynb` | Fits the ETAS model and simulates 30-day forecasts |
| 4 | `xgboost_model.ipynb` | XGBoost development notebook |
| 5 | `lstm_model.ipynb` | LSTM development notebook |
| 6 | `walk_forward_evaluation.ipynb` | Main model comparison (see below), including the GPS ablation |

The walk-forward notebook is the slowest, since it trains the LSTM many times.

**Re-downloading the raw data (optional):** run `python pipeline/fetch_usgs.py`, `python pipeline/fetch_gps.py` and `python pipeline/fetch_faults.py` from the project root, then `python pipeline/validate.py`. Note that the UNR GPS data used here (IGS14 reference frame) ends in August 2024.

## Evaluation method

Models are compared with **walk-forward evaluation**: for each year from 2021 to 2025, every model is trained only on data from before that year and tested on that year, with a 30-day gap so no training label overlaps the test year. 2019 and 2020 are used only to choose model settings. Forecasts are scored on the 1st of each month (PR-AUC, ROC-AUC and Brier score), and every model is scored on exactly the same rows. ETAS is fit once per test year and, for each monthly date, simulates the next 30 days using every earthquake up to that date.

## Results (M3.5+, 2021-2025, 32 qualifying forecast months)

Pooled PR-AUC, using each model's within-year ranking (higher is better; a random guess scores about 0.05):

| Model | PR-AUC | ROC-AUC |
|---|---|---|
| ETAS | 0.119 | 0.744 |
| Historical base rate | 0.126 | 0.736 |
| XGBoost | 0.127 | 0.699 |
| XGBoost without GPS | 0.116 | 0.692 |
| LSTM (seed 42; 5-seed mean PR-AUC 0.119) | 0.133 | 0.699 |
| LSTM without GPS (seed 42; 5-seed mean PR-AUC 0.112) | 0.120 | 0.707 |

- **ETAS** is fit once per test year and forecasts each month from all earthquakes up to that date (300 simulations per forecast). It beats the base rate in 4 of 5 years on per-year PR-AUC and has the best ROC-AUC of any model, but its probabilities run high (average forecast 8-12% vs. 2.5-10% actual).
- Neither ML model beats the historical base rate. With seed 42 the LSTM edged it (0.133 vs 0.126), but across 5 seeds its mean PR-AUC is 0.119: below the base rate and equal to ETAS. That single-seed lead was luck of the seed.
- The GPS result holds up better. Removing GPS made **both** ML models worse in 4 of 5 test years, and the LSTM with GPS beat the LSTM without GPS in 4 of 5 seeds (mean 0.119 vs 0.112). This supports strain rate adding information.
- The effects are small. Every 95% bootstrap interval for a difference between two models includes zero, so with only 32 qualifying months the results are suggestive rather than conclusive. All models do rank risk usefully: their top 10% of forecasts were followed by an M3.5+ about 15-17% of the time, against 5.3% for a random guess.

## Known issues and limitations

- **Windows / PyTorch:** `torch` must be imported before other libraries (such as geopandas), or it can fail with `WinError 1114` (a DLL conflict). The notebooks already import it first.
- **`etas` package:** installed directly from GitHub, and also needs `seismostats`; both are in `requirements.txt`.
- **Few events:** M4.0+ produced only 11 evaluation events, too few to compare models, so the main results use M3.5+.
- **GPS coverage:** only 8 stations, and some fault sections are more than 150 km from the nearest one. GPS data ends in August 2024.
- **Calibration:** the ML models' probabilities are only approximately corrected for class weighting, so their Brier scores are less reliable than their ranking metrics.
- **ETAS runtime:** the walk-forward ETAS forecasts take about 40 minutes, so they are saved to `data/processed/etas_walk_forward_predictions.parquet` and reloaded on later runs. Delete that file to recompute them.
